# Эльторг: версия для заказчика

В публикации доступны только:

- Главная: index.html#home
- Каталог товаров: index.html#catalog
- Схема JCB с деталями снизу: pins-bushings-stacked.html#all
- Карточка товара: index.html#product?id=valve
- Корзина: index.html#cart
- Оформление заказа: index.html#checkout (после добавления товаров)

Карточки товаров открывают отдельные страницы с галереей, характеристиками,
совместимостью, сопутствующими товарами и аналогами. Кнопки покупки в каталоге,
подборках и на товарной странице добавляют товар в общую корзину.
Другие страницы и варианты схем не включены в публикацию.

Ветка client-preview предназначена для GitHub Pages. Полная рабочая версия
сохранена отдельно в локальной папке home-preview.

Публичный сайт: https://lprchns-alex.github.io/eltorg-jcb-home-preview/

Товарные данные предварительные. Цены и совместимость требуют подтверждения.
Каталог содержит 9 исходных товаров и 35 демонстрационных позиций.
Позиции с артикулом DEMO-* используют условные цены,
иллюстративные изображения и непроверенную привязку к брендам техники.
Перед рабочим запуском их нужно заменить товарной выгрузкой заказчика.
Форма подготавливает заявку для передачи менеджеру; автоматической отправки
и оплаты на сайте нет.

## Тестовое оформление заказа

В `index.html` явно включён `order-mode=demo`. Оформление собирает ФИО или
название организации/ФИО ИП, телефон, email и ИНН для бизнеса (10 или 12 цифр).
Комментарий необязателен. Проверяется формат ИНН, не существование организации.
После успешной проверки появляется подтверждение с префиксом TEST: письмо
не отправляется, менеджер заказ не получает. Оформленные количества удаляются
из корзины; состав и контакты видны в подтверждении до перезагрузки страницы.
Контакты не записываются в localStorage, остаются только в памяти вкладки.

Корзина хранится в `eltorg-cart-v1` в формате `{version: 2, updatedAt, items}`
10 дней с последнего изменения, в том же браузере и на том же домене.
Просмотр страниц срок не продлевает. Старый массив автоматически мигрирует
без потери позиций. Очистка данных браузера или приватный режим могут удалить
корзину раньше. При недоступном хранилище работает память текущей вкладки.
Это не резервирование товара и не фиксация цены.

Для рабочей отправки нужно отдельно реализовать и подключить HTTPS endpoint
в `order-endpoint`, затем убрать `order-mode=demo`. Клиент отправляет JSON
`{customer: {type, name, phone, email, inn}, comment, items: [{id, quantity}]}`
и заголовок `Idempotency-Key`. Только ответ 2xx с
`{status: "accepted", orderId: "..."}` подтверждает отправку и очищает позиции.
Пустой endpoint, сеть или ошибочный ответ не дают ложного подтверждения.
Серверного обработчика в этом статическом демо пока нет. Он должен повторять
валидацию, получать товары/цены из доверенного каталога, защищаться от спама,
обеспечивать идемпотентность и отправку на согласованную рабочую почту.
SMTP-пароли и другие секреты нельзя помещать в файлы GitHub Pages.

Проверка логики: `node --test tests/*.test.cjs` (Node.js 20+).
